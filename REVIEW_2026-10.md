### Other security (lower priority)

- Public export endpoints open by default when `LB_EXPORT_TOKEN` unset, and span all firms. Fail closed in production; prefer header over `?token=`.
- No CSRF token; cookie is `SameSite=Lax`, so XSS on any sibling subdomain (dt./spv./lb.) can POST to CRM. Add an Origin check on state-changing routes.
- `matter_rates` read/replaced by `matter_id` without firm check.
- Inbound-email secret compared with `!==` and accepted via query string.
- TOTP codes replayable within their window.
- Pay/share tokens stored plaintext (reset/invite tokens are hashed).
- Backups are whole-DB, not per-firm.
- `express.json` limit 20 MB globally.
- Secretary (rank 40) can change matter billing terms (`editContacts`).
- Matter number reissued when client changes; `closed_at` not cleared on reopen.

## B. Recommendations

### Stripe
- **IOLTA fee routing is the key decision.** By default Stripe nets fees from the deposit, i.e. from client trust funds. Use **Stripe Connect**: operating account as platform, trust as a connected account, **destination charges** → Stripe fees come from the platform (operating) balance and the gross amount transfers to the trust account (LawPay-equivalent).
- Handle `payment_intent.processing`, `charge.dispute.*`, ACH returns; store `event.id` for dedup.
- Store refunds as separate negative rows (partial refunds currently mark the whole payment refunded).
- Refund API from the CRM instead of "refund in the Stripe dashboard".
- Capture `balance_transaction` fees and reconcile payouts (Stripe deposits are net-of-fee batches).

### Bank connection / Plaid
- **Plaid = read-only feed for the firm's own operating + IOLTA accounts.** Slot in as a third `bank_transactions.source` beside Mercury/OFX: `plaid_items` table (access token encrypted with existing `encryptSecret`), link-token + exchange endpoints next to `/api/firm/payments`, `/transactions/sync` cursor in the (unused) `mercury_sync_state.last_cursor` generalized per source, account→role (operating/trust) mapping. Plaid's `removed[]` fixes the returned-transaction gap.
- **Stripe Financial Connections** (not Plaid) for client bank verification at checkout — built in, no second vendor.
- Mercury sync: include pending transactions, overlap the start date, add the designed cron.
- OFX dedup key should include ACCTID.
- **Three-way reconciliation report:** bank balance vs. trust ledger vs. sum of client ledgers, monthly, with a saved sign-off.

### Client account mechanics
- Retainer record per matter (one-time/evergreen, minimum, top-up target); trust `matter_id` required; per-matter balances everywhere.
- Statement of account per client and per matter (invoices, payments, adjustments, trust activity, running balance, `asOf`), PDF.
- Unapplied-credit table instead of refusing overpayment.
- Intake: conflict-check gate before a matter goes active; engagement-letter status + signed date; `matter_parties` (adverse, opposing counsel, judge, related) included in conflict search; entity clients as first-class (not `primary_contact_*` fields).
- Close-matter workflow: block with unbilled WIP / open AR / trust balance; close reason; retention-until date; immutable matter number.
- Soft delete (archive) for contacts and matters; audit-log every money-moving and lifecycle action.
- Portal v2: one client-level link (all invoices, per-matter trust balance, replenish button, shared docs); automated reminders/dunning; auto-send generated recurring invoices.

### Layout / usability
- Mobile: collapsible sidebar under 768px (fixed 220px today), 16px inputs on mobile (iOS zoom), pointer events for calendar drag.
- Sticky modal footer (only `.modal-body` scrolls).
- Link `<label>`s to inputs (168 unlinked); `autocomplete="new-password"` + `minlength` on reset/invite.
- Shared `withBusy(btn, fn)` for all save buttons.
- Keyboard shortcuts: `/` search, `n` new, `t` timer.
- Inline forgot-password form instead of `prompt()`; strip `ssoToken` from URL and show SSO errors.
- Cross-tab inactivity (BroadcastChannel/localStorage).
- Close modal on clean navigation/back; show LinkedIn on contact detail; stronger confirm for "delete matter".
- Dark mode (≈96 hard-coded colors to tokenize).
- Frontend XSS: clean — `el()` uses text nodes/`setAttribute`; no exploitable sinks found.

### Infrastructure
- Off-site continuous backup (Litestream → S3/R2) + tested restore; single SQLite file on one Render disk today.
- Tests: start with money paths (invoice totals, payments, refunds, void, trust balance/overdraw).
- Split `server.js` (6.3k lines) into auth / billing / trust / payments modules.
- Move money to integer cents, at least trust + payments.
